# Project rules

These rules are binding for all work in this repository.

1. Never add Claude as a contributor or collaborator on this repository, or anywhere else. Do not add AI attribution lines to commits or pull requests.
2. Keep the project in a clear, organized folder structure.
3. Create a new code file only when it is genuinely necessary. Prefer extending an existing file over adding a new one.
4. Do not create per-task completion markdown files, progress logs, or similar throwaway docs.
5. No emojis anywhere in the project.
6. No em dashes anywhere in the project. Use a comma or period instead.
7. Add meaningful, concise comments throughout the code, explaining non-obvious decisions, not restating what the code already says.
8. Do not commit or push the internal product requirements document to GitHub, and do not reference it by name in any file that gets pushed.
9. Keep git commit messages concise. Do not reference week, phase, or milestone numbers.
